# HoldDetector

ボルダリング壁の写真を撮影し、ホールドを手動登録して、その登録済みホールドから課題を作る Android アプリです。

自動画像認識は使わず、ユーザーが壁情報を手動で整備していく前提の構成です。

## 概要

このアプリでは、次の流れで壁データを作成できます。

1. 壁を撮影する
2. リーチの目安を設定する
3. ホールドを追加・削除する
4. ホールドにスタート候補 / ゴール候補の属性を付ける
5. ホールドの持ちにくさを点数化する
6. その情報をもとに課題を生成する

## 特徴

- 自動画像認識なしで、手動登録に特化
- ホールドは矩形ではなくポリゴンで管理
- タップ/ドラッグで塗った範囲から外周を抽出してホールド化
- 壁ごとにリーチの目安を設定可能
- ホールドごとに以下の属性を付与可能
  - スタート候補
  - ゴール候補
  - 持ちにくさスコア
- 課題作成時に以下を調整可能
  - 抽選範囲
  - 使用ホールドの点数レンジ
  - ホールド数上限
  - 迂回の強さ
  - ルートのうねり
  - 途中ホールドのばらつき
  - ルート帯の太さ
- 課題難度の暫定表示あり
- デバッグ表示で各手の計算内容を確認可能

## 現在できること

### 壁データ作成

- 一覧から新規壁を作成
- CameraX で壁を撮影
- 壁上の 2 点と参考長さ(cm)を使って、リーチの目安を設定
- ホールドの追加・削除
- ホールド属性設定
  - スタート候補
  - ゴール候補
- ホールド点数設定
  - 左上から順に 1〜5 点で採点
- 壁データの保存 / 上書き保存 / 削除

### 課題作成

- 既存壁から課題作成へ遷移
- 作り方を選択
  - スタート/ゴール指定生成
  - スタート/ゴールおまかせ生成
- 抽選範囲をフリーハンドで指定
- 使用するホールド点数の下限・上限をレンジスライダーで指定
- ホールド数上限を指定
- 生成パラメータの詳細調整
- 生成結果の確認
- 生成後の手動微調整
- 課題難度と核心の表示
- 各手のデバッグ情報表示

2. 写真撮影
3. リーチの目安設定
4. ホールド追加・削除
5. ホールド属性設定
6. ホールド点数設定

一覧 → 写真撮影 → リーチの目安設定 → ホールド追加・削除 → ホールド属性設定 → ホールド点数設定 → 保存して課題作成

### 既存壁の編集フロー

一覧 → 編集ダイアログ → 以下のいずれかを選択

- リーチの目安設定
- ホールド追加・削除
- ホールド属性設定
- ホールド点数設定

### 課題作成フロー

課題作成画面は内部的に次のステップへ分かれています。

1. 作り方選択
2. 共通設定
3. 方法別生成
4. 結果確認
5. 詳細調整

## 課題生成の考え方

### 候補ホールドの絞り込み

課題生成時は、以下を順に使って候補ホールドを絞り込みます。

- 抽選範囲
- ホールド点数レンジ
- リーチ制約

### スタート/ゴールの決め方

- 手動生成では、ユーザーがスタートとゴールを指定
- おまかせ生成では、以下を優先して自動選択
  - スタート候補属性付きホールド
  - ゴール候補属性付きホールド
- 候補属性が無い場合は、抽選対象ホールドからランダムに選択

### ルート生成

内部では、スタートからゴールへ向かう複数の仮想ルート候補を作り、その近傍にあるホールド群から課題を組み立てます。

主に次の要素でルートが変化します。

- 迂回の強さ
- ルートのうねり
- 途中ホールドのばらつき
- ルート帯の太さ

### リーチ制約

壁上で設定した 2 点と参考長さから px/cm を求め、各手の到達可能性判定に使います。

現在の到達モデルは楕円ベースです。

- 横方向の基準: 120cm
- 縦方向の基準: 60cm

## 課題難度

課題生成後は、各手の難しさから課題全体の暫定難度を算出して表示します。

現在は概ね次の要素を使っています。

- 前ホールドの点数
- 次ホールドの点数
- その 2 点間の距離補正
- 核心となる 1 手

また、デバッグ表示では各手について以下を確認できます。

- 手順番号
- 計算後難度
- 距離(cm)
- `(前点数 + 次点数) x 距離倍率`

## 保存対象

現在保存しているのは壁データのみです。

- 写真
- ホールドポリゴン
- ホールド属性
- ホールド点数
- リーチの目安設定
- 壁タイトル

以下はまだ保存していません。

- 生成した課題そのもの
- 課題の難度結果
- 課題の手順番号

## UI 方針

- 白ベース、つや消し寄り
- ホールド番号は通常表示しない
- 課題作成時のみ手順番号を小さく表示
- `S / G` 表示あり
- ヘッダ・フッタは固定帯で、内容との境界を影で表現
- ボタンは押下感がわかる共通コンポーネントを使用

## アーキテクチャ

MVVM をベースにしつつ、UI 以外のロジックは以下へ分離しています。

- `ui/screens`
  - 画面 Composable
- `ui/components`
  - 再利用 UI 部品
- `ui/canvas`
  - キャンバス描画やジェスチャー処理
- `ui/selectors`
  - 画面用の派生状態
- `domain/challenge`
  - 課題生成や難度計算
- `domain/hold`
  - ホールド点数順などのロジック
- `data`
  - 保存 / 読み込み

## このリポジトリの位置づけ

このアプリは、ボルダリング課題作成支援のための実験的なプロトタイプです。

目的は次の 2 つです。

- 壁データを人手で整備できること
- その整備済みデータから、課題生成の試行錯誤を高速に回せること

今後も、UI の整理、課題生成ロジックの改善、難度計算の改善を中心に更新していく想定です。
